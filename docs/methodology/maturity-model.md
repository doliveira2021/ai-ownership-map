# Maturity Model

## Purpose

The maturity model measures how consistently an AI security capability is implemented across the organization.

## Scale

| Level | Name | Description |
|---|---|---|
| 0 | Not Established | No formal capability exists. |
| 1 | Reactive | Practices are informal, inconsistent or implemented mainly after issues occur. |
| 2 | Emerging | Initial processes and controls exist but are incomplete or inconsistently applied. |
| 3 | Defined | A documented and standardized process exists across relevant areas. |
| 4 | Managed | Controls are consistently implemented, measured and governed. |
| 5 | Adaptive | The capability is continuously monitored, risk-driven and improved; automation is used where appropriate. |

## Overall maturity interpretation

- 0–19: Level 0 — Unaware / Not Established
- 20–39: Level 1 — Reactive
- 40–59: Level 2 — Emerging
- 60–74: Level 3 — Defined
- 75–89: Level 4 — Managed
- 90–100: Level 5 — Adaptive

## Design rule

Questions should provide capability-specific descriptions for all six levels rather than asking users to select an abstract number.

## Applicability

Questions marked Not Applicable should be excluded from the denominator rather than treated as a maturity failure. Applicability rules must be explicit and auditable.
